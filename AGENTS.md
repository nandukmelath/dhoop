# Working on Dhoop

Dhoop is a voice guide for rooftop solar, built on Agora's `agent-quickstart-nextjs`. Read `README.md` first: it explains what the app does, how to run it and where each part lives.

## Shape

- Next.js 16 App Router, React 19, TypeScript, Tailwind.
- Voice: `agora-rtc-react` for microphone and camera, `agora-rtm` for transcripts and agent state, `agora-agent-client-toolkit` and `agora-agent-uikit` for the transcript and visualizer.
- Server: `agora-agents` starts the agent. The agent's settings are in `lib/dhoop/agent.ts`.
- Tools: defined once in `lib/dhoop/tools.ts`, served by `app/api/tools/[name]/route.ts`, and called by Agora's cloud with the `x-dhoop-key` secret.
- State: one session per conversation in `lib/dhoop/store.ts` (memory plus a best-effort file). Screens poll `app/api/session/[sid]`.
- Numbers: every constant and its source is in `lib/dhoop/config.ts`. The maths is in `lib/dhoop/solar.ts` and is covered by `scripts/test-dhoop.ts`.

## Rules that keep voice working (inherited from Agora's starter)

- `useJoin`, `useLocalMicrophoneTrack` and `useLocalCameraTrack` are gated by the `isReady` flag in `components/ConversationComponent.tsx`. Do not remove it; React StrictMode would create tracks twice.
- `useJoin` owns `client.leave()`, the track hooks own their tracks, and `usePublish` owns publishing. Never call `leave()`, `close()` or unpublish by hand. Mute with `track.setEnabled()`.
- Tokens must come from `RtcTokenBuilder.buildTokenWithRtm`. An RTC-only token breaks transcripts.
- The agent's UID lives in `lib/agora.ts` and must match on both sides.
- Initialise `AgoraVoiceAI` only after `isReady && joinSuccess`.

## Rules for signing in to Agora (found the hard way)

- `agora-token` is pinned to 2.0.6, and `agora-agents` to 2.14.0, in `package.json`. agora-token 2.0.7 changed the parameters of `ConvoAITokenBuilder.buildToken`, while agora-agents 2.14.0 and 2.15.0 still call the older form. Together they build sign-in tokens that live one second, and Agora answers "Token is expired", sometimes rather than always. Before loosening either pin, run `npm run test:dhoop`: one test reads the lifetime out of a token.
- A call made straight on `client.agents` (as `agentSay` in `lib/dhoop/quotes.ts` does) must pass `agoraAuth()` from `lib/dhoop/server.ts` as its second argument. The SDK signs only what an `AgentSession` does and its own `stopAgent()`. Anything else is refused with "Invalid authentication type".

## Rules for Dhoop

- The agent must never state a number it did not get from a tool. Add or change numbers in the tools, not in the prompt.
- Tool names use letters and digits only. All tool arguments are required, because Agora fills a fixed JSON body template.
- Values arrive from Agora as strings or numbers. Coerce them in the tool with the `num` and `str` helpers.
- Anything a screen imports must be free of server-only modules. `lib/dhoop/store.ts` uses `node:fs`; import only its types on the client.
- Agora keeps a conversation's history only while its agent is running. `saveConversation` (`lib/dhoop/memory.ts`) copies it into the session before an agent is stopped, and the next agent gets it in its instructions. Stop agents only through `/api/stop-conversation`, or call `saveConversation` first. Otherwise Dhoop forgets what was said, which is how it first shipped.
- The toolkit numbers transcript turns per agent, so a restarted agent overwrites the earlier lines on screen. `ConversationComponent` sets the shown lines aside when `restartCount` goes up. Bump it in `DhoopApp` whenever the agent is restarted inside a call.
- To test a conversation without a microphone, type in the box under the microphone button. It reaches the agent like speech, tools included.
- Dhoop finds the building itself (`lib/dhoop/findroof.ts`, used by the `findMyRoof` and `findBuilding` tools and by taps on the satellite view). Outlines come from one large PMTiles file read over HTTP (`lib/dhoop/buildings.ts`); OpenStreetMap's public Overpass servers were tried first and were timing out, and OpenStreetMap alone has almost no buildings in small Indian towns. A found roof has `source: 'found'`. The camera survey measures whatever the camera sees, so its tab is not the default and it must not overwrite a found roof on its own.
- Location is live. The browser watches its position for the whole call and reports it (`shareLiveLocation` in `DhoopApp.tsx`). The first report of a call always moves the home, even over a place left from an earlier call; later ones move it only while `session.followDevice` is true and the device has gone more than 25 m. Naming a place, tapping a building or drawing a roof sets `followDevice` to false so the device cannot undo the person's choice. Keep that rule when adding any new way to set the home.
- When a location report moves the home, the screen tells the agent with a short text in round brackets (the `nudge` prop of `ConversationComponent`), and the agent then calls `findMyRoof` and speaks up. The model otherwise tends to say "please allow location" and stop, without calling the tool.
- The satellite view must not ask for a closer picture than exists: the imagery service answers with grey "Map data not yet available" tiles, with HTTP 200, so nothing fails loudly. `lib/dhoop/imagery.ts` asks the service's tile map first. Keep any new map on that path.
- A building asked for by name goes through `findBuilding` → `findNamedRoof` (`lib/dhoop/findroof.ts`) → `namedPlace` (`lib/dhoop/places.ts`). Things learnt the hard way: (1) Two lookup services are asked at once. Nominatim orders answers well and returns the building's own outline, but wants exact spelling and is sometimes slower than six seconds; Photon forgives spelling ("Vidhan Soudha") but has no outlines. Nominatim's answer is waited for 2.5 seconds, then Photon's is taken. (2) Bus stops, stations and roads carry the names of the buildings they serve and often come first, so `pickNamed` puts them last. (3) When the map holds the place as a building, its own outline is the roof; nothing is guessed. (4) Otherwise the building is picked from the footprint data by `chooseNamedBuilding`: the main building within reach, not the nearest, because the middle of a palace's grounds is nearest to a kiosk. (5) Photon also matches on addresses, so a mall the map does not name comes back as a shop inside it: `sameName` spots that, the person's own name for the place is kept, and the agent is told the match is not exact. (6) Like every way of naming a place, it sets `followDevice` to false. It also drops the earlier roof and design: they belong to another building, and so does a saved bill, which the agent is told.
- Listening is set up in `buildAgent` and measured with `npm run listen:test` (a Murf voice speaks into a real call through headless Chrome; about two minutes of agent time a run). What the measuring taught: (1) One keyword can stop Agora's recogniser for a whole call. With "Patna" in `keywords`, alone or among a hundred others, the engine sent "The speech recognition service failed" (asr, code 1000) every ten seconds and heard nothing, five runs in six. No document says which words do this, so run the listening test after adding any name to `lib/dhoop/hotwords.ts`. (2) The same error comes when the microphone track is muted with `setMuted`: no sound reaches Agora at all. Hold-to-talk therefore turns the volume to nothing with `setVolume(0)`. (3) The app recovers from that error by itself: `onListeningFailed` → `recoverListening` in `DhoopApp.tsx` restarts the agent with `listening_failed`, and the server gives the new agent the other recogniser (`chooseListening` in `lib/dhoop/agent.ts`): ARES fails, Deepgram with its terms takes over; Deepgram fails, ARES with the short keyword list does. The new agent opens with `RECOVER_LINES` ("Sorry, I missed that…"), because whatever was being said was lost. Up to four times a call, never with the microphone refused, and not within eight seconds of the last restart, when the old agent's last complaints can still arrive. The failed recogniser is remembered for twenty minutes (`noteListeningFailed`), and new calls start on the other one meanwhile. This replaced "restart once with the short keyword list": on 20 Nov 2026 around noon both ARES lists failed to start in 4 calls of 6 each ("Connection timeout after 10 seconds", then "The speech recognition service failed"), after 0 of 10 that morning, and Deepgram failed in 3 of 10. So no setup is safe by itself, and the cause is not in the keyword list alone. `plain_listening` now only means the microphone is refused. (4) End of speech is `semantic`. With plain silence detection a one-second pause before a name split every sentence in two. (5) Agora's speaker lock (`sal`) is off. Its seamless mode locks onto whoever speaks clearly first, which in a hall is a neighbour, and then the caller is not heard at all. With a voice sample (`sample_urls`, a bare 16 kHz `.pcm` of 10 to 15 seconds) it silenced the neighbours but cut the place names out of the caller's sentences, and one start was refused with ErrInternal. (6) Deepgram's `keyterm` is one string in Agora's API; Dhoop joins several with `&keyterm=`, which Agora accepts. Whether Deepgram then treats them as several has not been measured.
- The keyword list is capped at `SAFE_HOTWORDS` (30). Short soak calls on 20 Nov 2026: about 114 keywords, the recogniser failed to start in 2 of 4; 30 keywords, 0 of 10; the first 7, never. The names that were misheard in tests come first in `PLACES`. Do not raise the cap without soaking it again.
- The roof is changed by voice through three tools: `changeRoof`, `nextBuilding` and `undoRoofChange` (`lib/dhoop/roofedit.ts`, with the geometry in `lib/dhoop/reshape.ts`). What to keep in mind: (1) Sides are as the person sees the picture, north at the top, but a roof grows along the building's own walls: `facing` snaps "right" to the wall direction nearest east, so a rectangle at an angle stays a rectangle. (2) Growing splits the outline at its two widest points seen from the side that moves and slides the front half out; the area gained is exactly width times distance for any shape. The result is checked (no crossing walls, area within 2%), and an outline that fails grows evenly all round instead, which the agent is told. (3) Leaving a part out is a straight cut across, placed by halving until the area is right. (4) The tool converts square feet and percent. The model passes the number and the unit as spoken, so no arithmetic is left to it. (5) A redrawn roof is saved with `source: 'found'` and `foundBy: 'voice'`, and `roofKey` in `Stage.tsx` includes the roof's area, because the satellite view is only rebuilt when its key changes and a grown rectangle keeps its first corner and its number of corners. (6) Each change is kept in `session.roofSteps` with a mark of the roof it led to (`roofMark`). Undo works only while that roof is still the one on screen, so a roof found or drawn afresh never "undoes" to a building somewhere else. (7) After any of the three, `afterRoofChange` in `tools.ts` sizes the system again: one the roof was holding back grows, one the bill decided stays. (8) Like every way of choosing a roof by hand, they set `followDevice` to false. `npm run listen:test -- roof` with `DHOOP_LISTEN_GAP=14` speaks all four requests into a real call and prints what Dhoop did.
- Call time is the scarcest thing this project has. On 20 Nov 2026 at about 3 PM the Agora console showed 168 of the 300 free minutes used, most of them by listening tests and soak calls that day, which were under-counted while they ran (each call costs its start and teardown too, not only the speech). So: do not run `npm run listen:test`, `npm run smoke` or any script that starts a call unless the person asks for it, and say what it will cost first. `/dev`, `npm run film:reveal`, `npm run test:dhoop` and the headless page checks use none. The app guards the rest: `lib/dhoop/quiet.ts` decides when a call nobody is using ends itself (four minutes, thirty seconds of warning; `?quiet=0.15` shortens it outside production, which is how it was proved in a 40-second call), and `idleTimeout` in `app/api/invite-agent/route.ts` is 45 seconds.
- How close the satellite view opens is one line in `SatelliteRoof.tsx`: two levels past the deepest real picture where that is `SHARPEST_ZOOM`, one level past it elsewhere. Two past a level-18 picture, on a screen with doubled pixels, was an eight-times blow-up in which nothing could be made out.
- `wholeBuilding` in `lib/dhoop/buildings.ts`: the footprint data sometimes draws an annexe or a piece of a roof apart from its building. A named point, or a device, that falls in an outline under 60 square metres with one three times its size within five metres gets the larger one. A tap still gets exactly the outline tapped.
- `moveRoof` slides an outline without changing it (`shiftRing`), for when it does not sit on the roof in the picture. It moves along the picture's own directions, not the building's walls, and refuses more than 60 metres: that is another building, which is `nextBuilding`'s job.
- The connection panel (the dot beside End) used to spring open on every engine error and hang off the right edge of the screen. A recogniser failure the app is already recovering from is now added quietly, the list is cleared when a new agent takes the seat, and the panel opens leftwards.
- A test cannot import from a component file: `components/ConversationComponent.tsx` pulls in the Agora SDK and React, and the whole test file then fails to load, with one unhelpful line. Logic worth testing goes in `lib/dhoop/`, as `quiet.ts` does.
- `pause_state_enabled` in the end-of-speech settings (`lib/dhoop/agent.ts`) is off, and must stay off. With it on, Agora's engine takes a sentence that trails off as "hold on" and waits in silence for more instead of answering. A person thinking aloud in Malayalam ("...and there, for me") left a call looking stuck that way on 20 Nov 2026. The SDK's own note on the field says as much. Not re-tested by voice, to save call minutes.
- `findSolarSite` → `findSite` in `lib/dhoop/site.ts` answers "where should I build a solar farm". Learnt while building it: (1) The Global Solar Atlas also covers the sea off the coast, where its "elevation" is the seabed. Open water has no buildings and plenty of sun, so it won every coastal comparison until spots at or below sea level were dropped. (2) A district is rarely the shape of its box: the grid keeps only spots inside the border Nominatim returns (`polygon_geojson`, simplified), and is made finer until at least twelve fall inside. (3) The sunniest few spots differ by a percent or two, so among them the land decides (`pickSites`): open, then scattered houses, then built up. (4) Names: the recommended place is named by Nominatim's reverse lookup at zoom 13 (village, taluk, district), one call, because that service allows one a second. The runners-up try Photon, which stopped answering after a burst of parallel calls during testing, and are otherwise described by how far they lie from the first. (5) Overpass timed out for substations, so grid access is listed as not checked. Do not let the agent imply otherwise. (6) The tool races a 12.5 second timer, inside Agora's fifteen, and the data is remembered, so a second ask is quick. (7) The screen stays on the site until a roof tool runs (`beforeTool` in `tools.ts`) or the roof changes (`updateSession`).
- `throughTheYear` in `lib/dhoop/solar.ts` turns the place's twelve monthly sunshine figures into units a month for a system. A test holds it to the design: the twelve months must add up to the design's own yearly figure within two percent. With no monthly figures (the national average was used) it returns null and the screen draws nothing, never an invented curve. `designSolar` hands the best and poorest month to the agent as `through_the_year`.
- `comparePlaces` (in `lib/dhoop/site.ts`) ranks named places by the Atlas's yield. The "sun hours" shown beside a place are on a panel at its best tilt (`GTI_opta`), not on flat ground: with flat-ground hours Jaipur showed fewer than Kochi while winning on yield, which read as a mistake.
- The passbook takes `?lang=` and so does its voice route; `voiceNote(session, lang)` writes the note in that language. The share link carries the choice.
- From the end-to-end test of 20 Nov 2026 (one tap-driven call of 142 seconds, two of about 25, one spoken): (1) The model answers from what it already knows. Asked "what should I install?" after a design exists it does not call `designSolar` again, and a test that waits for the tool reports a failure that is not one. Check what was said, not only what was called. (2) In a headless test, CDP's `Browser.grantPermissions` for location alone refuses every other permission, the microphone included: that call ran in the plain typed-only setup. Grant them together. (3) Asked "why not the second place?", the model reached for a percentage that belonged to a different comparison. Each runner-up now carries its own `against_the_first` sentence. Give the model the comparison it will be asked for, in words. (4) It said "saves 2,720 rupees a month after the subsidy"; the saving is on the bill and the subsidy on the price, and the prompt now says so.
- The solar story is `components/dhoop/Story.tsx`, started by the `playSolarStory` tool, the button under "Take it home", or a `story` post to the session. What building it taught: (1) Its script is the passbook's voice note with `short`, split a sentence to a subject (`StoryPart`), and each sentence is a scene. (2) The whole clip is fetched before it plays. Played as it arrives, the browser reports its length as endless until the end, and the scenes had nothing to keep time by: the title sat for forty seconds and then jumped to the last scene. (3) Murf takes eight or nine seconds over half a minute of speech. So the narration is made ahead: `afterTool` in `tools.ts` calls `warmStory` after every tool once a system exists, and `speak` in `lib/dhoop/voice.ts` keeps each clip and makes two askers wait for one request. Without that the room looks at a title for ten seconds. (4) A tool that "needs a roof first" is a tool the model will refuse to try when it believes there is none. `playSolarStory` says to call it at once and let it report; told otherwise, the model asked for the bill instead of calling it. (5) The film sends `dhoop:story` events and the call screen turns the microphone down while it plays. (6) It is played once per asking: `Stage.tsx` remembers the key it has played and ignores a story more than two minutes old, so a reload does not replay it.
- Words sent to the agent in the first two or three seconds of a call are lost: the agent has not joined yet. The "Try" prompts stay greyed out until it has.
- The practical side of a solar farm (`siteDetails`, and `also_worked_out` in `findSolarSite`'s answer) is fetched with the place, not asked of the person. The person's complaint that led to it: Dhoop found a plot and then could not say where the substation was or who could build on it. (1) Substations: `lib/dhoop/grid.ts` reads OpenInfraMap's vector tiles at level 11, the tile the spot is in and the eight round it, layer `power_substation_point`. Every public Overpass server tried on 20 Nov 2026 was at capacity or timed out, and Nominatim does not find substations by the word. The map knows place, voltage and operator; it does not know spare capacity, and small substations are often missing. (2) Vendors: `lib/dhoop/vendors.ts` is a dated copy of the national portal's registered vendors, read in a browser: a list for every state and union territory (the vendors with the most installations in the state) and a district's own list for two districts. `vendorsFor(district, state)` gives the district's where there is one and the state's otherwise; `vendorsShown` in `site.ts` turns that into what a screen shows, and `vendorsForModel` into words, which say in capitals that a state's list is NOT picked for being near. The `findVendors` tool answers "who installs solar in Jaipur?" for any place, or "here": one question to Nominatim with the address asked for, taking the first answer that names a state (the first answer for "Leh" is a boundary filed under no state). The portal's list is served through its own access check (`/authenticate/api/verifyAccess/...`, with a token step). Do not write code that imitates that from the server. How the lists were read, for doing it again: open pmsuryaghar.gov.in, "Registered vendors". Apply stays greyed out until a district is chosen, so a state alone cannot be listed: choose the state's main district and set the order to "State Wise Installations DESC"; the figures shown are then the state's (the Tamil Nadu list read under Chennai has vendors from Vellore, Coimbatore and Erode). Wait for the list to change after Apply (it shows the previous list for some seconds, which caught one reading here). A vendor's number appears a moment after its row is opened, and only one row stays open at a time. In a browser pane that is not on screen the page's menus half-close and swallow the next click; opening each row and choosing from the menus by script, one state every ten seconds or so, was steadier than clicking. Afterwards compare what was typed into the file with the page by checksum, numbers and the first letters of each name: `vendors.ts` holds over two hundred phone numbers and one wrong digit rings a stranger. Business name and number only: not the contact person's name or email, no entry whose "vendor name" is only a person's name, and no proprietor's name tacked on to a business name. Leave out vendors shown with no installation in the state. Tried in one typed call of about half a minute on 20 Nov 2026: asked "Who installs solar in Jaipur?", the model called `findVendors` once, said they were Rajasthan's busiest, named the first two with their ratings and read a number out a digit at a time when asked. (3) Money: `farmMoney` in `lib/dhoop/site.ts`, from `FARM` in `config.ts`, each figure with its source. Where a state's own price a unit is not known a range is given and called a range. (4) The model once read "open land will have to be found nearby" back as "there is open land nearby". The answer now carries `the_land_there`, which says NOT clear ground in so many words. Write a negative so that no part of it can be lifted out as a positive.
- Three things added on 20 Nov 2026, evening: the week's forecast (`sunForecast` → `sunWeek` in `lib/dhoop/outlook.ts`), the 25-year view (`longRunSavings` → `longRun` in `lib/dhoop/longrun.ts`) and changing language by voice (`changeLanguage`). What to keep in mind: (1) The session keeps what does not go stale and the screen works out the rest. `session.week` holds each day's sun hours, not units, and `session.longRun` holds only the price rise asked for; `WeekCard` and `LongRunCard` in `Stage.tsx` do the sums from the design on the screen, so a system resized by voice never sits beside last minute's figures. The week goes when the home moves a kilometre (`placeMark` in `store.ts`), and stays when the roof is only redrawn. (2) The best day is the best day still to come (`bestAhead`). The first version said "best day: today" at eight in the evening. (3) The forecast's daily weather code calls a day "overcast" that has more sun than a usual one, so the sky's word comes from the sunshine itself against the month's usual day, with "rain likely" from the chance of rain. (4) A price rise is the person's own "what if", held to ten percent, and every text says it is not a forecast. (5) An agent cannot change language: it listens and speaks in one for its whole life. `changeLanguage` only leaves `session.langAsk`. `Stage.tsx` sees a new key and sends a `dhoop:language` event; `switchByVoice` in `DhoopApp.tsx` gives the old agent 1.8 seconds to finish "One moment", restarts through the same `switchLanguage` the language chips use, and 2.5 seconds later nudges the new agent to say where things stand. No clocks are compared (a phone's and the server's differ): the key that was in the session when the screen opened is ignored, and only a new one acts. (6) Chart marks use `--chart` in `globals.css`, the marigold's hue three steps deeper. The marigold itself is 1.9 to 1 against the card, which is fine for a button with an ink border and too faint for a thin bar or a line; `--chart` is 3 to 1 and more. New charts: one colour for one series, bars no wider than 24 px with no border, figures on the one or two marks that matter, the rest on hover, on focus, and in a table under the chart. (7) From the one real call that tried all three (20 Nov 2026, about two minutes, typed): the forecast and the 25-year answer were right and the screen did change to Kannada by itself, the Kannada voice saying the resume line. Three things went wrong and were put right. With no system designed the forecast answered for one kilowatt, and the model read "4.5 units" out as what the roof will make: every figure now carries "from EACH kilowatt of panels". Asked for the long run before a design, the tool said "design it first"; the model designed it, read the design out, and never came back to the question: both tools now work a system out themselves when the bill is known (`designIfBill` in `tools.ts`) and say that they did. And ten seconds after the change to Kannada its recogniser failed to start, the recovery brought another agent, and the summary that had been asked of the first was never spoken: `recapOwed` in `DhoopApp.tsx` asks it again of whoever comes back, for forty seconds after a change by voice. That last fix has not been seen working in a call. (8) Three short calls later that evening, to hear the summary. The first taught nothing, through the test's own fault: it typed its request two seconds in, and the agent had not joined. The greeting's words are on the screen before the agent is in the call, so they prove nothing; the "Try" prompts coming alive is the sign, and a script should wait for that and two seconds more. The second and third each opened with a recogniser that failed to start, first Agora's own and then Deepgram, and Dhoop's "Sorry, I missed that"; asked again, as a person would, the third went through in 35 seconds: "One moment", the Kannada resume line, and then the summary in Kannada with the system's size and the monthly saving. Two things it showed were put right. The nudge appeared in the transcript as a long line of English the person had not said: lines that are wholly in round brackets and not the agent's are now left out of the transcript (`isNudge` in `ConversationComponent.tsx`), the location nudge with them. And the Kannada sentence had one Chinese character in the middle of it, from the model; the prompt for every language but English now says that one character from another writing system is a mistake. Neither has been seen in a call since.
- Added late on 20 Nov 2026: "right now on your roof" (`powerNow` → `roofNow` in `lib/dhoop/today.ts`, sums in `lib/dhoop/power.ts`, `NowCard` in `Stage.tsx`) and the saying-again of a lost line (`unanswered` and `owed` in `ConversationComponent.tsx`). Keep in mind: (1) An appliance never "cannot run". A home with rooftop solar stays on the grid; the sun only decides how much of it is paid for. The tool's answer says YES in capitals and gives the share the sun covers now and at the best hour, and the prompt repeats it, because "can I run my AC?" invites a no. (2) The reading for this moment can stand above the best hour's average (one is an instant, the other a mean), which read as a mistake on the card: the best hour is shown as at least what it makes now. (3) The hours are averages over the hour that ends at each index, so they are drawn at the middle of that hour. (4) `power.ts` holds the sums because `today.ts` imports the session store, which a screen cannot. (5) With a failed recogniser Agora's engine answers nothing, typed lines included, until the app has brought a new agent in. A line sent in those seconds was simply lost. It is now said again three seconds after the new agent joins (or twelve seconds after the restart, should the joining go unseen), but only when the old agent never began a turn of its own after the line, the restart follows a failed recogniser reported in the last twenty seconds, and the line is under 45 seconds old. A change of language owes nothing. Erring towards not saying it again is deliberate: "add 300 square metres" said twice is worse than a tap lost. The first version also took the agent's state moving to thinking or speaking as "answered"; in the one call that tried it (`?stt=ares!bad` on the address makes the first recogniser fail on purpose) the state moved, nothing was answered, and the line was not said again. The agent's state is not evidence that it answered. The page writes `[dhoop]` notes to the console at each step, for whoever tries it next; the reworked version has not been seen saying a line again in a call. A second call was tried: the recogniser did not fail that time (the forced failure works about five times in six, and the twenty-minute memory of a failed recogniser can move the call to the other one), the typed line was answered at once, and the page noted "typed line answered" and said nothing again, which is the half of the rule that must never go wrong. That call also showed the model asking for the bill before it would call `powerNow` ("I need to know your monthly electricity bill first"): the bill was saved, but by the test and not by the agent, so the model did not know. The three lookups' descriptions and the prompt now say to call first and never to ask first; the tools know what is saved. Not seen in a call since. And a test's own lesson: end a test call the moment the agent has answered. That call sat for fifty seconds waiting for a tool that was never going to be called. Two more short calls that evening. In the first the recogniser failed for real nine seconds in, and the page noted "agent restarting: line unanswered yes, after a failed recogniser yes, owed yes": the decision is right. The test then took the new agent's "Sorry, I missed that" for the answer and hung up two seconds before the line was due to be said again, so the saying itself is still unseen. In the second the recogniser worked, and asked "Can I run my AC on it right now?" the model said it would check and then asked "just the AC, or anything else?" without calling `powerNow`. ## Hosting

- The tour is `/tour` (`app/tour/page.tsx`), for a judge with no microphone or one minute: ten fixed steps in `lib/dhoop/tour.ts`, run one at a time by `app/api/tour/[sid]/route.ts` through the same `beforeTool`, `run` and `afterTool` a call uses, so the screen is the real one and the data is live. No agent is started and no call minute is used. Three rules keep it honest and safe. The visitor sends only a step's number, never a tool or its arguments. Only a session named `tour-…` (which only the tour page makes) can be driven this way. Ninety steps a minute across everyone, because each may ask a free map or weather service a question. The page calls itself a tour; never present it as a call. Adding a step means adding it to `TOUR`; a test checks every tool it names exists.
- The hackathon's hall is found by the names people say. The open map knows the building as "Divyashree Technopark" and not as the school in it, so `SAID_AS` in `lib/dhoop/places.ts` turns "Polaris School of Technology" and the estate's spellings into the name the map has. Add a line there when a place people will certainly ask for is known to the map by another name. Do not use it to paper over a building the map lacks.
- The logo is drawn by `/brand` (`app/brand/page.tsx`) and the files in `brand/` are pictures of that page: `npm run brand`, with the app running, Google Chrome and a Mac. The same run rewrites the tab and home-screen icons in `public/` and the card a shared link shows (`public/brand/dhoop-social-1200x630.png`, named in `app/layout.tsx`). The blocks on that page are exact pixel sizes because they are photographed; do not make them responsive. The sun in the files is `SunMark.tsx` standing still: change one, change the other. `FIELD-NOTES.md` is the list of what Agora and Murf did in real calls, with counts; add to it only what was measured.
- Weather has two sources, because the first fails on the hosted copy. Open-Meteo counts requests by the address they come from and Render's free servers share theirs: on 20 Nov 2026 the hosted copy was refused within a second, every time, while this laptop was served. So `forecastAt` (`lib/dhoop/outlook.ts`) and `sunToday` (`lib/dhoop/today.ts`) fall back to `lib/dhoop/sky.ts`: MET Norway's cloud cover, the sun's position by arithmetic, a clear-sky figure and the share cloud takes. Keep in mind: (1) it is an estimate, and `via` on `session.week` and `session.now` makes the screen and the agent say so; never remove that label. (2) Measured against Open-Meteo for six towns over a week: median difference 16%, mean 1% low, worst day 144% (broken cloud; two weather models disagreeing, and one crude formula). Delhi's clear days come out a sixth high, because the clear-sky sum knows nothing of haze. (3) MET Norway refuses callers that do not name themselves, so the `User-Agent` stays; it carries the app's public address and nothing personal. (4) It has no chance-of-rain figure for India, so `rainChance` is absent from the second source. (5) Days and hours are in Indian time by a fixed five and a half hours. (6) `DHOOP_WEATHER=clouds` forces the second source, to test it; a refusal by the first is remembered for ten minutes (`skipFirst`). An outside service that works from a laptop proves nothing about the host: after adding one, run the tour's steps against the hosted copy.
- The first building lookup after every restart of the hosted copy failed: the outlines file's index took longer to fetch from there than the twelve seconds a lookup is given. `warmBuildings` in `instrumentation.ts` now reads the index and two demo places at start, in production only, trying for about a minute and a half. A lookup in another city still fetches that city's part of the index the first time, which can take several seconds. The tour's route also tries a step a second time when an outside service let it down.
- The hosted copy is https://dhoop.onrender.com, made on 20 Nov 2026 from Render's Blueprint page for this repository. A push to `main` builds and replaces it by itself, in about four minutes; conversations in progress are lost when it does. It was checked the same evening: the pages, the token service, a typed bill and its passbook without a call, and then one 11-second call in which Agora's cloud reached `saveBill` and `setLocation` on the host and the sunshine lookup worked from there. Render's form hides a pasted key as twelve dots once its box loses focus; the dots are not the value.
- The hosted copy runs on Render from `render.yaml`: the plain Node way (`npm ci --include=dev`, `next build`, `next start`), one free instance in Singapore. `--include=dev` matters: the build needs TypeScript and Tailwind, which are development packages, and a host that sets `NODE_ENV=production` leaves them out. Node is pinned to the version the app was tested on.
- One instance only, and not a serverless host. Conversations live in the server's memory (`lib/dhoop/store.ts`), and Agora's cloud calls the tools on the same server the screen is reading from. On a host that runs each request wherever it likes, the tool would write to one copy and the screen would read another.
- `publicBaseUrl` in `lib/dhoop/server.ts` takes `PUBLIC_BASE_URL` first, then the address Render says it gave the app (`RENDER_EXTERNAL_URL` or `RENDER_EXTERNAL_HOSTNAME`), then Vercel's. On Render nothing is set by hand.
- `instrumentation.ts` runs once at start. With `DHOOP_KEEP_AWAKE=1` it asks for the app's own status page through its public address every ten minutes, so a free server is not asleep when a judge opens the link. It works the address out itself and does not import `server.ts`, so starting the server does not load the call machinery.
- `/api/status` on the hosted copy says which commit is running (`build`), which is how to tell that a push has gone live.
- A phone that will not give its location: the first person to open the hosted copy on an iPhone got "this device did not share its location" and nothing else. The hosted site sends no header that blocks location; the refusal is the phone's. On an iPhone every browser has its own switch under Settings, Privacy & Security, Location Services, and until it is on a page is refused without the person being asked. `lib/dhoop/whereami.ts` turns the browser's three answers (refused, no position, too slow) into what to do on the device in the hand; `findMine` in `SatelliteRoof.tsx` tries once more for a rougher fix when it was only slow, and keeps a refusal apart from a network fault; and when the call's own request is refused as it starts, `shareLiveLocation` sends `dhoop:location-fault` and the map's card says so. Not tried on an iPhone by the person who wrote it.
- In a production build the development doors are shut: `?dev=1` on a tool is refused (401), `?stt=` and `?quiet=` do nothing. `/dev` still opens, with buttons that are refused. `npm run e2e` therefore needs the development copy.
- The Dockerfile was rewritten for npm (the starter's used pnpm, which this project has no lock file for) and has not been built: the machine it was written on has no Docker.
- Before the first upload every file to be committed was searched for the real values in `.env.local`, for email addresses, home-folder paths and recordings. None were found. Do that again before making the repository public.

## Checks

```bash
npm run typecheck
npm run test:dhoop
npm run verify:api
npm run build
```

`npm run e2e` runs every tool the way the agent does, then the passbook and its voice note in all six languages, every page, and the doors that must stay shut: about seventy checks, with the app running in development. It starts no agent and uses no call minutes. Run it after any change to a tool.

`npm run show:agent -- hi` prints the settings that would be sent to Agora, without contacting it.

`npm run film:reveal` checks the roof reveal. It needs the app running and Google Chrome installed, and uses no agent time. Run it after any change to `SatelliteRoof.tsx`, `Stage.tsx`, `panels.ts` or `imagery.ts`.

`npm run listen:test -- en` measures how well the agent hears place names, in a real call. It needs the keys, the app running and Google Chrome, and uses about two minutes of agent time. Run it after any change to `lib/dhoop/hotwords.ts` or to the listening settings in `lib/dhoop/agent.ts`.

`npm run demo` is demo day in one command (`scripts/demo.mjs`): build, `next start`, a Cloudflare quick tunnel, checks, and the addresses. Two things it learnt on its first rehearsal. A port is free when nothing answers on it, not when a listener can be opened: with the dev server on every address, a second listener still got 127.0.0.1 and the script then talked to the dev server. And a new tunnel's name must be looked up through public name servers (1.1.1.1), because a laptop that asks its own resolver seconds after the tunnel opens is told "no such name" and keeps believing it for minutes. The public address reaches the app through `PUBLIC_BASE_URL` in the environment of `next start`; nothing is written to `.env.local`.

`npm run smoke` is the live check. It needs the keys in `.env.local` and the app running. It starts a real agent in each language, reads its status from Agora, asks it to speak, and stops it, which uses a few seconds of agent time per language. Run it after any change to `lib/dhoop/agent.ts` or to the Agora packages.
